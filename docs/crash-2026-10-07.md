# Launch crash investigation — 7 October 2026

## Evidence and conclusion

The user supplied two macOS crash reports, from 22:13:57 and 22:14:09 Hong Kong time. Both report `EXC_CRASH (SIGABRT)` with DYLD termination before application code ran. DYLD describes `@rpath/libssh2.1.dylib` as missing, but its detailed reason is that the **existing bundled library's ad-hoc signature was rejected by library validation**: the process and mapped library did not have matching Team IDs.

These were genuine failed launches during build validation, not intentional shutdowns or a SwiftUI/session crash. Both reports describe the same earlier executable. A later corrected local Release build launched successfully. Do not interpret DYLD's summary as proof that the file was physically absent.

## Root cause

The earlier Release app combined ad-hoc signing with hardened runtime, while bundled protocol libraries were also ad-hoc signed (no Team ID). Hardened runtime library validation rejected them before Swift started. Normal signature verification alone did not catch this runtime configuration error.

## Fix and prevention

- Local Debug and Release default to `ENABLE_HARDENED_RUNTIME=NO`; build.sh explicitly uses that setting and `CODE_SIGN_IDENTITY=-`.
- The packaging phase rejects ad-hoc signing when hardened runtime is enabled instead of shipping a bundle that cannot start.
- verify-bundle.py checks final bundle signatures, matching teams, arm64-only binaries, relocated dependencies and macOS 27 minimum. It also invokes `--verify-bundle-launch`, which exits before UI/storage initialization but exercises DYLD. build.sh runs this check automatically.
- For distribution, enable hardened runtime **with a real Developer ID identity**, sign every bundled library with it, verify the resulting bundle and notarize. Do not disable library validation to hide a signing mismatch.

Original crash reports contain personal paths/system identifiers and are not copied into the repository. This finding explains those two reports only; investigate any later crash against its own timestamp, executable identity and stack trace.

## Incremental packaging follow-up — 8 October 2026

A DMG-build check found a separate resource-seal failure after an incremental Xcode build: the always-running native packaging phase replaced bundled libraries, while final app signing was skipped. build.sh now removes only its generated Release app product before building, forcing Xcode to recreate and sign the complete bundle while retaining compiler/dependency caches. Repeated builds and verification of the app inside the mounted DMG passed. This is separate from the earlier hardened-runtime launch crash.
